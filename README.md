# Юридическая практика Евгении Бычихиной

Многостраничный сайт юридических услуг на Next.js 16 / React 19. Основное production-размещение — Timeweb Cloud App Platform, данные и заявки хранятся в Timeweb Managed PostgreSQL.

## Что включено

- главная страница и четыре страницы услуг;
- страницы «Обо мне», «Стоимость», «Контакты»;
- политика конфиденциальности и согласие на обработку данных;
- адаптивное меню и формы для desktop, Android и iPhone;
- закрытая страница `/upravlenie` для контактов, цен, стажа, расписания и журнала заявок;
- PostgreSQL-журнал со статусами, заметками, поиском и необратимым обезличиванием;
- короткие уведомления без персональных данных через Telegram, email, MAX и webhook при наличии настроек;
- Schema.org, sitemap.xml, robots.txt и llms.txt;
- клавиатурная доступность и поддержка `prefers-reduced-motion`.

## Основное размещение и автодеплой

Источник production-кода — ветка `main` репозитория `Nskandre/legal_service_site`. Timeweb App Platform автоматически собирает и разворачивает новый commit из `main` через `Dockerfile`.

Cloudflare Worker сохранён только как совместимый резервный runtime. Автоматическое обновление активного Cloudflare-размещения должно оставаться остановленным до отдельного прямого поручения владельца.

## Локальная проверка

Требуется Node.js 22.13 или новее и npm с `package-lock.json`.

```bash
npm ci
npm run build:timeweb
npx tsc --noEmit
npm run lint
```

Резервную Cloudflare-сборку можно проверить локально без публикации:

```bash
npm run build
node --test tests/rendered-html.test.mjs
```

Запрещено запускать `wrangler deploy` или иным способом обновлять Cloudflare без отдельного прямого решения владельца.

## Переменные Timeweb

Безопасные имена переменных перечислены в `.env.example`. Реальные значения задаются только в настройках приложения Timeweb и не попадают в Git.

Обязательные production-переменные:

- `DATABASE_URL`, `DATABASE_SSL` — подключение к Managed PostgreSQL;
- `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` — вход и защищённая сессия `/upravlenie`;
- `NEXT_PUBLIC_SITE_URL=https://legservice.ru`;
- `LEAD_RETENTION_DAYS=180`.

Каналы уведомлений включаются только полными парами настроек:

- Telegram: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`;
- MAX: `MAX_BOT_TOKEN`, `MAX_CHAT_ID`;
- email: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `LEAD_NOTIFICATION_EMAIL`;
- webhook: `LEAD_WEBHOOK_URL`, при необходимости `LEAD_WEBHOOK_TOKEN`.

Для текущей почты используются `smtp.yandex.ru`, порт `465`, защищённое соединение и адрес `legserv24@yandex.ru`. Пароль хранится только в Timeweb и локальном закрытом хранилище владельца.

## Как обрабатывается заявка

1. API проверяет обязательные поля, согласие и ограничение частоты.
2. Полная заявка сначала сохраняется в PostgreSQL.
3. Для настроенных каналов создаются записи в `delivery_outbox`.
4. Во внешнее уведомление передаются только номер заявки и ссылка на защищённый журнал.
5. Сбой внешнего канала не превращает уже сохранённую заявку в ошибку для посетителя; доставка повторяется из outbox.

## Управление сайтом

Публичные контакты, стаж, цены и свободные слоты изменяются на `https://legservice.ru/upravlenie`. После входа нужно изменить нужные поля и нажать «Сохранить изменения»; данные сохраняются в PostgreSQL и появляются на сайте без commit и повторного deploy.

Тексты страниц, структура, стили и программная логика изменяются в репозитории. После проверок изменения сохраняются commit и push в `main`; Timeweb запускает автодеплой. Контакты по умолчанию находятся в `app/lib/content.ts`, но production-значения из админки имеют приоритет.

## База данных

Схема создаётся миграциями из `migrations`. Контейнер перед запуском выполняет `scripts/migrate.mjs`, затем запускает Next.js. Основные таблицы:

- `site_config` — изменяемые публичные настройки;
- `leads` — заявки;
- `lead_events` — история действий;
- `delivery_outbox` — очередь уведомлений и ошибки доставки;
- `rate_limits` — защита формы и входа.

Прямое редактирование production-базы не используется для обычной работы. Владелец управляет заявками через `/upravlenie`, а резервными копиями и состоянием сервиса — через панель Timeweb.

## Безопасность

- не добавлять `.env`, токены, пароли, cookies и данные заявителей в Git;
- не передавать персональные данные в уведомления;
- не удалять production-базу, приложение, домен или резервные копии без отдельного поручения;
- после изменений проверять сборку, типы, lint, тесты, ключевые маршруты и desktop/mobile;
- сведения об услугах, ценах и применимых юридических требованиях подтверждать перед публикацией.
